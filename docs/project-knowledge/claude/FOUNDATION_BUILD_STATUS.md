# Foundation build status

First implementation milestone delivered, per APP_BUILD_SEQUENCE_V0.md's build order: B0 gate + B1 (contracts, parsers, fixtures), plus the persistence-foundation and seed-data items the milestone asked for ahead of full B3/B4. **No UI, no workout generator** — those stay out of scope until B4/B5 as the build sequence specifies *(update: B5 has since been built — see the note above)*. Delivered to Nelson as a zip (`personal-training-os-foundation.zip`); the code does not live anywhere durable yet (no GitHub repo pushed — see deviations).

## What's built

- **Repo scaffold**: package.json, tsconfig (strict), Vite, Vitest, Playwright configs. Runtime deps exactly `react`, `react-dom`, `zod`; dev deps `typescript`, `vite`, `@vitejs/plugin-react`, `vitest`, `@playwright/test`, `yaml`, plus `@types/node`, `@types/react`, `@types/react-dom` (needed for typecheck; not in the architecture doc's dev-dependency list — a deviation, see below).
- **`src/domain`**: ids (type-prefixed UUIDs), time (Intl-based, DST-correct — tested against the 2026-11-01 and 2027-03-14 America/Los_Angeles transitions), canonical JSON, FNV-1a 32/64 (verified against published test vectors), mulberry32 + the ECR-02 seed/draw default, and the Markdown pipe-table parser shared with the fixture loader (D-119).
- **`src/contracts`**: Zod schemas + inferred types for every declaration in APP_DATA_CONTRACTS_V0.md §4–§10 (primitives, vocab, document base, exercise/equipment/profile/constraint/config, Datapack, CheckIn, Generation, Workout, ExternalSession, UserActionEvent, Settings, PackHistory, StateSummary, Meta, Backup), with the invariants Zod can express (R06/R06_choice, R04/R04b, set reps-xor-seconds, workout ended_at ≥ started_at, ALLOY session id/env_id/log_mode, hard-constraint bindings, etc.) as `.superRefine` checks.
- **`src/pack/decode.ts`**: the FX-META/FX-EQUIP cell decoders (equipment options, roles, laterality, load mode, tag/sore lists, Y/N, load lists) — shared, per D-119, with what the real datapack tool (B2) will use on EXERCISE_METADATA.md/EQUIPMENT_MODEL.md. The pack *loader* itself (`validatePack`, V-00a–g) is explicitly not built yet — that's B2/B5 *(update: `validatePack`'s engine-side V-00a–g logic has since been built as part of B5's `pool.ts` and wired into the facade; the pack-authoring tool itself, B2, is still not built)*.
- **`src/store`**: the four-method `StorageAdapter` interface, `MemoryAdapter` (used by tests), and a hand-written `IndexedDbAdapter` (db `pto`, store `docs`, keyPath `id`) per §10.1–§10.2. Write queue, backup export/import, and migrations (the rest of B3) are not built yet.
- **`src/engine/index.ts`**: the facade's *shape* only (`validatePack`, `replay`, `promptsDue`, `generate`, `swapOptions`, `servability`, `equipmentImpact`) — every function throws "not implemented"; no rule logic. This is deliberate: B5 is test-first against GENERATOR_ACCEPTANCE_TESTS_V0_2.md and hasn't started. *(update: B5 has since been built — see `B5_GENERATOR_BUILD_STATUS.md`. Every facade function except `replay()` is now real.)*
- **`tests/architecture.test.ts`**: enforces the §6.3 module-boundary graph and engine purity (no Date.now/new Date()/Math.random/localeCompare/window/indexedDB/navigator under src/engine) by statically scanning imports and file contents.
- **`tests/fixtures`**: a copy of GENERATOR_ACCEPTANCE_TESTS_V0_2.md §3 (FX-CONFIG prose, FX-EQUIP table, FX-META Appendix A — all 81 rows) plus a loader that parses it through the shared table parser/decoders. A test confirms 81 rows, schema validity, and a handful of the doc's own claims (e.g. exactly 11 PLANK_POSITION_UNCONFIRMED rows, VPULL capability gating).
- **`dev-data/`**: a small representative seed datapack (8 exercises, one per family; 4 equipment items; profile/constraints/config) generated by `generate-seed.mjs` and validated against `DatapackSchema`. The minimal UI shell (`src/ui/App.tsx`) loads and validates it at runtime — this is the "verify the application runs" check, smoke-tested headlessly (Vite build + preview + Playwright/Chromium page load, zero console errors besides a missing favicon).

## Deviations from spec (flagged, not silently resolved — per APP_BUILD_SEQUENCE_V0.md §7)

1. **No GitHub repo / Cloudflare Pages** (§1.3 B0 setup). This sandbox has no GitHub/Cloudflare account access. `git init` + one local commit was done instead; the zip is the handoff artifact. Nelson needs to push it to a private repo and wire up Cloudflare Pages himself (or ask a future session to do it if repo credentials get connected).
2. **DECISION_LOG_addendum_D096-D120.md not written to the project** (§1.3 lists this as a B0 setup step; the content already exists verbatim in APP_TECH_ARCHITECTURE_V0.md §20). Treated as a documentation task outside this milestone's code-only scope — flagging rather than silently doing or skipping it.
3. **Extra dev dependencies**: `@types/node`, `@types/react`, `@types/react-dom` were added beyond APP_TECH_ARCHITECTURE_V0.md §3's listed dev-dependency set. Required for `tsc --noEmit` to pass with Node built-ins and JSX; no runtime effect, but this is a deviation worth a decision entry if the pattern holds (§7: "New dependency: decision entry naming what it replaces" — these replace nothing, they fill a gap the architecture doc's list didn't anticipate).
4. **Fixture copy is not the full document**: `tests/fixtures/GENERATOR_ACCEPTANCE_TESTS_V0_2.md` carries §1–§4 and Appendix A verbatim (what the B1 fixture loader actually reads: FX-CONFIG, FX-EQUIP, FX-META) but omits §5–§9 and Appendix B/C to keep the fixtures directory from duplicating the entire ~50-page canonical test doc. Said explicitly in that file's own text rather than silently passed off as the full document. *(B5 update: the project's canonical, unabridged copy — with Appendix B/C — was read directly from the project for `tests/engine/acceptance.test.ts`'s exact-value tests; the local abridged copy was left as-is since the loader only ever needed §3/Appendix A.)*
5. **Engine facade types are placeholders** (`unknown` for GeneratorState, CompletionDecision, etc.) — intentional per B5 not being started, not an oversight. *(update: superseded — B5's real `GeneratorState` type is now used throughout the facade.)*
6. **npm audit** reports 5 moderate/high/critical advisories, all in dev-only tooling (`vite`/`esbuild`/`vitest`'s mocker), not runtime deps. Left as-is rather than force-upgrading to breaking major versions outside this milestone's scope; worth a routine dependency-update pass per §17.
